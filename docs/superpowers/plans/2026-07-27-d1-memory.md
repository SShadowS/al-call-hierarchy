# d1 memory (plan)

Branch `feat/d1-memory`, base `70a4f8b` (master).

Scoped read-only first: `.superpowers/sdd/scope-d1-memory.md` (byte census + two probe
shapes) — **local scratch, gitignored (`.superpowers/sdd/.gitignore` is `*`), so it
exists in no clone.** Every load-bearing figure it produced is therefore restated in
full below and at its use site in the source; nothing tracked cites it for a number.
**Every number below is measured**; the census names its method per figure.

## What the census established (and corrected)

- **Process peak is 9,675 MB**, not the 11,825 quoted at kickoff — that predated the
  `feat/l3-substrate-and-parked-items` merge. Confirmed independently by the controller's
  own default-preset run at `70a4f8b`.
- **d1 contributes 3,743 MB of peak**, not ~4.3 GB. The 4.3 was a parent+children sum
  (`detector.d1-db-op-in-loop` is the parent span of `search_loops_cohorts` and
  `assemble_cohort_findings`). The honest measure is the peak d1 adds over the pre-d1 peak.
- **`rss_delta_mb` is commit-driven, not a live-bytes measure** — two runs of identical
  work disagreed by 500 MB on the same span, because the delta depends on how much freed
  heap the allocator reuses. **Use trace deltas for placement, a census for size.**
- d1 **does** set the process peak: it is reached inside `assemble_cohort_findings`, and
  all 42 other detectors together add 302 MB afterwards. d1 is 67.6 s of a 309 s run.

## The ceiling, stated before we start

d1's irreducible floor is **~190–250 MB live**; with allocator overhead a realistic
post-fix d1 is **~400–600 MB of peak**. **Sub-GB for the whole process is NOT reachable
here** — the process already stands at 5,932 MB *before* d1 runs. Landing d1 at ~500 MB
puts the process at ~6.2–6.5 GB with the L3 workspace and the cone substrate back on top.
This arc is measured against **d1's 3,743 MB**, not against sub-GB.

## Global Constraints (bind every task)

1. **Byte-identical output.** `scripts/check-goldens` (29 golden dirs across 9 targets)
   passes with **zero golden files touched**, and a DO-workspace `alsem analyze` run stays
   byte-identical. **Never blind-regen a golden.**
2. **No caps, sampling, or lossy truncation** — rejected by the user in the original d1
   arc. Every change here is representation and ownership only: same uncertainties, same
   witnesses, same findings.
3. `cargo check --all-targets` and `cargo clippy --all-targets --all-features` **zero
   warnings**. **`touch` changed files first** — a cached check prints "Finished" and
   proves nothing. Note `target/debug` was cleaned; the first check pays a full rebuild.
4. **A test must pin the USE, not just the helper, and must be proven able to fail** —
   see CLAUDE.md's Testing Philosophy. Five instances of that defect in the previous arc,
   all caught by review and none by the suite.
5. `rustfmt <file>` per file, never `cargo fmt`. Stage only intended paths, never
   `git add -A`.
6. **State the probe shape with every number.** `--detector d1-db-op-in-loop` and a
   default preset are different measurements and are never comparable.
7. Measure size with a census, not with `rss_delta_mb` (constraint set by finding 3 above).

## Task 1 — intern `CohortRep.uncertainties` (the largest single lever)

**~1.65–2.15 GB live, ~16–21 M allocations, zero output risk.** Replace the per-cohort
owned uncertainty payload with `Vec<u32>` ids into a run-level uncertainty table.
`uncertainty_lites` reads `kind`/`at` through the table; order is preserved.

Gate: goldens + DO byte-identical; census before/after for the *size* claim; trace for
placement only.

## Task 2 — shrink `Evidence`

**~940 MB of 1,055, ~14.8 M allocations, zero output risk.**
`Evidence { source, note }` → `{ source: &'static str, at: Arc<str>, kind: u8 }`, with the
`format!` deferred to `project_evidence`. `StableEvidence` must materialise the identical
`String` — that is the byte-identity argument and it needs a test that states it.

**As built (DONE):** `{ source: &'static str, note: Option<Arc<str>> }` — 32 B rather
than the planned shape's 40, with the `format!` moved UP to the interning boundary
(once per distinct uncertainty, 3,150 executions) rather than down to
`project_evidence` (7.4M). The planned `kind: u8` was rejected: `Uncertainty.kind` is
an open `String` from the L4 summary layer, so a discriminant would need a panic or a
`String` fallback for an eighth kind — a correctness hazard inside a change that is
meant to be representation only. Interning also makes the byte-identity argument
structural (the same `format!` expression with the same arguments, at a different
frequency) instead of a re-derivation that has to be proven equal. Measured: the
`confidence` bucket 1,055.5 MB / 14,924,347 allocations → 228.2 MB / 89,722; process
peak 7,531 → 6,434 MB. See `.superpowers/sdd/task-2-report.md`.

## Task 3 — the zero-risk remainder

**~180 MB combined**, all byte-identical by construction:
- share one witness between the sink and `cohort_contexts` (`Arc<WitnessSummary>` or
  move-on-finalize) — ~95 MB;
- intern `EvidenceStep`'s routine/callsite/op/anchor ids — ~50 MB;
- intern `affected_objects`, `&'static str` for `title`/`fix_options` — ~30 MB;
- `LoopSetRegistry`'s hash-cons index stores its words twice (`d1_cohort.rs:246-250`) — ~4 MB.

## Task 4 — stop building `evidence_path` for cohort-bearing findings

**~96 MB.** R4 already receives `Vec::new()`, so it is byte-identical there — but five
consumers read `finding.evidence_path` directly and must be moved to `flatten_witness`
themselves, each proven byte-identical: `format_sarif.rs:364`, `format_html.rs:198`,
`format_pr_summary.rs:118,146`, `format_policy.rs:123`, `actionable_anchor.rs:44`.
**This is the one task that moves where work happens** — treat its gate accordingly.

## Task 5 — re-measure and capstone

Re-run both probe shapes, record d1's contribution against the 3,743 MB baseline, update
CHANGELOG + `docs/OUTSTANDING.md`, and state the residual honestly.

## Deliberately NOT in this arc

**Interning `ctx.uncertainties_by_node` at the substrate (census item #10, ~650 MB).** It
subsumes Tasks 1–2's data model and would make them nearly mechanical — but it touches
**51 detector files** via `to_confidence`, and it is substrate work, not d1 work. Doing it
first would put the arc's biggest blast radius before its biggest win. Recorded in
`docs/OUTSTANDING.md` as the natural follow-on, with the sequencing note that it should
come *after* this arc, not instead of it.
